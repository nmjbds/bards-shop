# TikTok Seller Center — Onboarding Flow (Reference)
อ้างอิงจาก seller-th.tiktok.com/settle/* — เก็บไว้เทียบกับ apply.html ของ BARDS

## หน้า Intro (ก่อนเข้าฟอร์ม)
- หัวข้อ "3 ขั้นตอนเริ่มต้นขายสินค้า"
- List 3 step รวม: 1) ลงทะเบียนร้านค้า 2) รออนุมัติ (สูงสุด 7 วัน, มีลิงก์ "เอกสารที่จำเป็น") 3) ตั้งค่าร้านค้า
- ปุ่มเดียว "เริ่มต้น" เข้าฟอร์ม
- ลิงก์ "ออกจากระบบ" เผื่อ login ผิดบัญชี

## ฟอร์ม 5 Step (มี progress bar บอกตำแหน่งตลอด)

**Step 1/5 — ชื่อร้านค้า**
- ช่องกรอกชื่อ + character count (5/120)
- Preview การ์ดจำลองว่าชื่อร้านจะแสดงยังไงจริง (search result style)
- Tip box: ห้ามคำว่า "เรือธง"/"ทางการ", ห้ามใช้แค่ตัวเลข/อักขระพิเศษ/ภาษาที่ไม่ใช่อังกฤษ
- บอกไว้ว่าตั้งชั่วคราวได้ เปลี่ยนทีหลังได้

**Step 2/5 — หมวดหมู่สินค้า**
- Dropdown เดียว เลือกหมวดหมู่หลักของร้าน
- หน้าโล่ง มีองค์ประกอบเดียว

**Step 3/5 — ประเภทธุรกิจ**
- Radio card 2 ตัวเลือก: "รายบุคคล" (ไม่จดทะเบียน — ใช้บัตร ปชช.) / "องค์กร" (จดทะเบียน — ใช้ใบรับรองบริษัท)
- แต่ละตัวเลือกบอกล่วงหน้าว่าต้องเตรียมเอกสารอะไร

**Step 4/5 — อัปโหลดเอกสารยืนยันตัวตน** (เนื้อหาเปลี่ยนตาม step 3)
- กรณีรายบุคคล: อัปโหลดบัตร ปชช. → มี validation เช็คไฟล์ → auto-fill ข้อมูล (เลขบัตร, ชื่อ-สกุล, วันเกิด, ที่อยู่) จาก OCR + เตือนว่าต้องเช็ค/กรอกเพิ่มเองบางช่อง
- กรณีองค์กร: อัปโหลดหนังสือรับรองจัดตั้งนิติบุคคล (สูงสุด 3 ไฟล์) แทน
- มี error banner สีแดงชัดเจนเวลาข้อมูล/ไฟล์ไม่ครบ ("ต้องให้ข้อมูล" + รายละเอียด)
- ไม่มีข้อมูลบัญชีธนาคารในขั้นตอนนี้

**Step 5/5 — ข้อมูลติดต่อเพิ่มเติม**
- เบอร์โทร + อีเมล auto-fill จากบัญชีที่ใช้สมัคร (mask บางส่วน เช่น `+660****6304`, `h***l@gmail.com`)
- ตัวเลือก "ใช้อีเมล/เบอร์อื่น" ถ้าไม่อยากใช้อันที่ผูกบัญชี
- ปุ่มตา (เปิด/ปิด) ดูค่าเต็ม

## Popup ตรวจสอบข้อมูลก่อนส่งจริง (หลังกด "ถัดไป" จาก step 5)
- หัวข้อ "ตรวจสอบข้อมูลของคุณ" + คำอธิบายสั้นว่าจะใช้ยืนยันตัวตน
- สรุปทุกอย่างที่กรอกมาแบบ read-only: ชื่อร้าน, หมวดหมู่, ประเภทธุรกิจ, ข้อมูลบัตร (เลขประจำตัว, ชื่อ-สกุล, วันเกิด, ที่อยู่), เบอร์โทร, อีเมล
- Checkbox รับข่าวสาร/โปรโมชั่น (ติ๊กไว้ล่วงหน้า)
- ปุ่ม "ส่ง" (submit จริง) กับ "กลับ" (ปิด popup กลับไปแก้ไขข้อมูลในฟอร์มเดิมได้ ไม่ submit)

## หลัง submit สำเร็จ → /settle/verification
- "ลงทะเบียนเสร็จแล้ว" + "กำลังตรวจสอบเอกสาร โปรดติดตามสถานะที่หน้าแรกของ Seller Center"
- อ่านอย่างเดียว ไม่มีปุ่มแก้ไข
- ปุ่มเดียว "ไปที่หน้าแรก"

## ถ้าถูกปฏิเสธ → /settle/verification-result
- ข้อความปฏิเสธ + ปุ่มให้สมัครใหม่ (ลิงก์กลับหน้าแรก)

---

## ⚠️ จุดที่ apply.html ปัจจุบันของ BARDS ต่างจากมาตรฐานนี้ (ระบุโดยผู้ใช้)
- **มีช่องกรอกบัญชีธนาคารในฟอร์มสมัคร** — ผิดหลัก ไม่ควรเก็บข้อมูลการเงินก่อนได้รับอนุมัติ ต้องย้ายไปขอหลัง approve แล้วเท่านั้น
- โครงสร้าง/ลำดับ step, การแบ่งเนื้อหา, และ UI/UX โดยรวม "ยังไม่เป็นระบบ" เทียบกับมาตรฐานนี้ — รอผู้ใช้ระบุเพิ่มเติมว่าต้องการปรับ step ไหนบ้าง
